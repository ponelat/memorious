# Memorious archive

A lossless, plain-text copy of a Memorious journal: **every event** as JSON, a **JSON Schema** describing the events, and
the **media** in ordinary file formats. You do not need Memorious to read it.

> **This archive is not encrypted.** The journal on the device is encrypted at rest; the media files here are decrypted
> and the text is plain. Keep it somewhere you would keep the journal itself.

## What is in here

| path | what |
|---|---|
| `manifest.json` | what this export contains: counts, checksums, a record per media file, what was left out and why |
| `events.jsonl` (or `events.json`) | every event, ordered by `recorded_at` then `event_id`. One JSON object per line (or one array) |
| `schema/event.schema.json` | JSON Schema (2020-12) for one event |
| `schema/manifest.schema.json` | JSON Schema for `manifest.json` |
| `media/<hash>.jpg` `.m4a` `.mp4` | photos (JPEG), audio (AAC in an m4a/MP4 container), video (H.264/AAC MP4), decrypted, unmodified |

## The data model in one minute

The journal is an **append-only log of events**. Nothing is edited or deleted; later events change what a reader shows.

Every event has: `event_id`, `device_id` (who wrote it), `seq` (that device's counter), `recorded_at` (unix ms),
`kind`, and a `payload` tagged by `payload.type`.

| kind | meaning |
|---|---|
| `capture` | something recorded: payload type `text`, `photo`, `audio` or `video`. Media payloads carry `hash` (find the file at `media/<hash>.<ext>`), `size`, and for audio `audio_kind` (`voice` = a dictated note, `music`) |
| `annotation` | text attached to a target. To a capture's `event_id` it is a **transcript or caption** (latest wins). To a `dev-…` device id it is that device's **name**. To `journal:password-proof` it is key material |
| `redact` | hides the capture in `payload.target`. The capture's event is still here; its media bytes are left out of this archive |
| `token_set` | a hash of the browser passcode (never the passcode) |
| `infra` | plumbing: which devices joined (`peer_join`), app versions seen (`version_seen`), key rewraps (`key_rewrap`), and whether a device keeps revisions (`peer_policy`) |
| `ink` | the **drawing canvas**: one drawing op per event, see below |

To rebuild what the app shows: take the `capture` events, drop those named by a `redact`, and attach the latest
`annotation` for each. Voice recordings are usually *transcript only* after a week: the audio bytes may be missing
(`manifest.json` says `unavailable`) while the transcript is the record.

### The drawing canvas

Drawings are stored as ops in `ink` events: the payload is `{type: "ink", month: "YYYY-MM" (UTC), op, ...}` with the op's fields beside `op`. (Older journals stored the same ops as `infra` events with `infra_kind: "ink"`, `target` = the month and the op under `data`; both forms mean the same thing.) Each op is a stroke
(`tool`, `seed`, `size`, `pts` = `[x, y, pressure, tilt]`), an image placement, a `move`/`delete` of a lassoed region, or an
`undo`/`redo`. The canvas for a month is the fold of its ops in `recorded_at` order. Strokes are stored as a few points
plus a seed; the pixels are regenerated by the renderer, so there is no bitmap in the archive.

### Superseded events and stubs

An event may *supersede* earlier ones: a canvas `snapshot` op carries a month's folded drawing and lists, in `supersedes`, the ops it makes redundant. That is a statement about the data, never an instruction to delete anything. Each device decides for itself (a retention policy) whether to keep the superseded events or to **collect** them. A device announces which it does with a `peer_policy` infra event (`keeps_revisions: true|false`; the latest per device wins).

A collected event leaves a **stub**: same `event_id`, `device_id`, `seq`, `recorded_at` and `kind`, with the payload replaced by `{type: "collected", by: <the superseding event_id>, was: <the original payload type>}`. `manifest.json` counts the stubs. An archive taken from a device that keeps everything has none; one taken from a device that collects has stubs for them, and the snapshot holds the drawing. A peer that still has the full event can fill a stub.

## Open world: read these rules before writing an importer

* **Ignore properties you do not know; keep events you cannot interpret.** New properties and new `kind` / `payload.type` /
  `infra_kind` / ink `op` values appear over time. Properties are only ever added, never removed or renamed.
* **Event ids and `(device_id, seq)` are the identity.** Do not renumber.
* `recorded_at` is the author's clock and can disagree between devices; order by `(recorded_at, event_id)` as the app does.
* `format_version` in `manifest.json` changes only if this archive layout itself changes incompatibly.

## Verifying

`manifest.json` → `events.sha256` is the SHA-256 of the events file as written; each included media entry has its own
`sha256`. Every line of `events.jsonl` should validate against `schema/event.schema.json`.
